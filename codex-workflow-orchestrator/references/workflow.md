# Workflow

## 1. Intake

Create a short task contract:

- Objective
- User-visible outcome
- In scope
- Out of scope
- Constraints
- Done criteria
- Assumptions

If requirements are ambiguous, proceed with the safest narrow interpretation and record the assumption.

## 2. Repository orientation

Inspect, in order:

- root files
- README or docs
- package manager files
- test configuration
- lint/typecheck/build scripts
- existing implementation patterns
- existing tests near the target area

## 3. Planning

Before editing, write a plan with 3-7 concrete steps.

The plan must include:

- files or modules likely to change
- test strategy
- rollback/risk notes for risky changes
